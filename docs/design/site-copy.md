# 官网文案取舍

更新：2026-09-25。范围：`web/site` 中英文营销首页；不改法律正文、产品文档或真实软件的界面文字。

## 参考了什么

以下是对当日官网文案结构的观察，不是对其性能承诺的独立验证。

| 官网 | 写法 | Lyra 借鉴与不借鉴的部分 |
| --- | --- | --- |
| [Devin](https://devin.ai/) | 先定义产品角色，再展示测试、交付和协作场景。 | 先说明产品是什么；不照搬其交付保证、客户背书或性能数字。 |
| [Cursor](https://cursor.com/) | 简短定位后直接展示产品，能力介绍紧邻操作界面。 | 让工作区预览承担解释工作；不靠更多形容词解释“智能”。 |
| [Codex](https://openai.com/codex/) | 按工程任务、工作方式和使用入口展开。 | 用任务组织正文；不把 Lyra 写成只服务程序员的工具。 |
| [Claude Code](https://claude.com/product/claude-code) | 首屏列举任务，随后提供使用入口、演示与方案信息。 | 写具体动作和当前使用条件；已提供与规划中明确区分。 |
| [Qoder](https://qoder.com/en) | 按产品入口展开，并区分编程和更广泛的任务。 | 明确适用范围与各平台的发布状态。 |

这些网站也有口号、夸张表达和大量营销内容。本次不是照抄它们的语气，而是采用“定位—任务—产品演示—使用条件”的顺序。

## Lyra 首页写什么

1. 首屏保留已经确定的 `Anything? Lyra.`，不恢复说明小字和两个按钮。
2. 下一屏立即解释：电脑上的通用 Agent，以及浏览器、文件、编辑器、终端的关系。
3. 用三个操作场景展开：查资料和处理文件、改代码和运行命令、操作支持的桌面应用。
4. 解释模型连接、Skills、MCP；说清本地模式与数据完全不出设备不是一回事。
5. 保留交互界面预览与 Supabase 演示视频。预览文字说明如何操作，不暗示正在完整运行真实 Agent 任务。
6. 写清当前免费测试版及第三方模型费用边界。按用户要求保留 Pro / Max，明确标注规划中，不编造区别和额度。
7. 提供已有的桌面下载入口、直接的开发者联系方式和原有法律入口。

## 不写什么

- 不反复用“工作现场”“连续推进”“能力带回任务”代替具体动作。
- 不用“不是 X，而是 Y”构造不存在的对立，不贬低聊天或其他产品来抬高 Lyra。
- 不编造客户、效率提升、成功率、安全认证或性能数字。
- 不承诺全自动完成所有任务、控制所有应用、完全离线、永久免费或无限模型额度。
- 保留 Pro / Max 规划，但不把三个重复的“待定”当作权益列表，也不承诺开放日期。
- 保留移动端与 CLI 规划，说明独立下载和发布时间尚未确定；不暗示源码中已有的依附 Desktop 的 CLI 能力完全不存在。
- 不把“我不会提前承诺”等起草过程写给访客。
- 不为了避免套话而删掉用户确定的品牌 slogan；底部原句保留。

文档和实现能支持定位与使用边界，不能替代逐版本的发布验证。发布前仍需核对安装包、视频、模型接口与能力在实际发布版本中的状态。

## 维护规则

- 中英文分别自然表达，含义一致，不逐字翻译“现场”“入口”等内部用语。
- 正文优先用动作、对象和结果；标题不能代替说明。
- 一个事实只在必要位置解释，避免每段重新列一遍所有功能。
- `kill-ai-slop` 自动扫描只提供线索，尤其不能覆盖所有中文套话。
- 保留联系说明、隐私和条款文本，不把法律边界当作营销冗词删除。
- 本次不改壁纸、首屏布局及滚动效果。视觉验收由用户完成。
