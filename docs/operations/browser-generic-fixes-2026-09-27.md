## 关键边界

- 完整扫描与完整输出是两回事。超长文字可以被截断展示，同时使用完整扫描检查变化；未读完文档或 frame 时不能确认稳定。扫描有节点/时间预算，不把虚拟列表中尚未挂载的内容称为已读取。
- 多 frame 读取不再因主文档用完输出预算就跳过后续 frame。完整读取后组合各 frame 的文字指纹；同源和跨域 frame 的 busy/ready 状态参与等待。跨 frame 片段明确标注为 frameExcerpts。
- textContains 可以查到输出片段以外的已渲染文字。它只证明文字存在，不证明那是本次操作新产生的结果。
- textChanged 绑定本任务、同标签页、同范围、同预算的已读取完整基线。拒绝跨范围比较；目标等待不会拿一个 frame 的文本去和整页基线比较。
- 系统不自动追加发送、删除、确认点击；也不根据名称模糊相似度自动执行候选。没有页面证据就不声称业务完成。
- ToolSearch 的候选预算与定义加载预算分开，精确 select 仍按明确选择加载。已有会话的历史记录和已发现工具不会被这次修复偷偷清空。

## 后续优化记录

发送后仍依赖 agent 选择等待条件，系统没有自动保留“本次发送对应的新回复”的连续状态；输入后和点击后仍会内部重读控件地图。因此，减少可见 map 调用、输出差量和返回更完整信息，不等于底层已经只做局部更新，也不证明回复结束后的延迟已根治。后续需要按目标/操作维护有效性和明确完成信号，信号不足时保留未知，不能靠静默、历史回复的 Copy 按钮或固定延时猜完成。
