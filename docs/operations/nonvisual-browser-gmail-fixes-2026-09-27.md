# Gmail 会话问题修复清单：2026-09-27

对应 [原始调查与逐项时间线](nonvisual-browser-gmail-session-2026-09-27.md)。本文记录前一轮过程问题修复，当时按要求暂缓附件上传 G1；后续已单独实现，详见下方 G1 链接。

验收动作固定为：打开 Gmail 草稿页 → 新建主题和多段正文 → 修改指定文字格式 → 关闭再打开草稿。预期是不混入联系人 iframe 的地址、不把已写入的正文报为失败、不把每个段落当成输入框、不在英文页面等待猜测的中文标题。当前验证使用本地真实 Chromium/Electron，没有操作真实 Gmail 账号、发送邮件或调用 Gmail API；实际账号中的同一流程仍需复测。

## 已完成的代码修复

- [x] ~~G2：子框架污染主标签页身份。~~ 页内导航只在 `isMainFrame=true` 时更新主地址及主页面缓存；读取时以主 `webContents.getURL()` 为准。回归同时验证子框架导航不使主页面 targetRef 失效，以及真正的主框架导航正常更新。
- [x] ~~G3：正文写入成功却报 `input_not_accepted`。~~ 使用真实 Chromium 输入后，按仍连接的编辑宿主实际内容验证；页面截断、拒绝或替换宿主仍失败。监听不到 `input` 事件不再单独构成失败条件，事件只作为诊断证据。已在 Electron 复现“页面截断事件传播、正文保留、旧工具报错”的机制，但不能据此断言真实 Gmail 当时用了同一个事件处理器。
- [x] ~~G3：失败后没有真实值，误导重复输入。~~ 各输入路径返回实际内容预览及比较结果；密码不回显。批量输入指出失败字段；返回地图后再次校验失败时，清除先前成功回执，返回该字段的新状态。不会自动重写或提交。
- [x] ~~G3：忽略换行以及跨段落选区偏移。~~ 保留段落和空行，区分 Chromium 的空行占位 `br` 与真实换行，并按编辑器逻辑文本计算选区偏移。覆盖段落、格式包装、行内 `br`、开头/末尾空行；删除换行的页面处理器不能再被误判为写入成功。
- [x] ~~G4：富文本后代挤占地图。~~ 由编辑宿主拥有普通文字、段落和格式后代；真实的嵌套按钮、链接、角色控件仍可单独定位和点击。原两字段复现从 13 项降到 2 项，不靠增加地图数量上限。
- [x] ~~新增 G8：被销毁的请求遗留本地排队票或并发占位。~~ 队列票和请求许可都由生命周期自动释放，覆盖等待中的 future 被丢弃、执行中的 future 被丢弃、正常返回与取消。旧实现的三个回归测试均失败，修复后均通过；后续请求可以继续取得许可。现有会话不足以证明该隐患触发了历史上的 90 秒等待。

## 已修正的工具与提示契约

- [x] G5：`read(query)` 明确是显示文字搜索，不是按输入框名称读取内容；无匹配时提示 `map(query)`，不能声称字段为空。浏览器场景提示、工具目录和错误恢复指引保持一致。
- [x] G5：导航后查看页面地图；文字等待使用页面实际语言和具体结果，不等待翻译/猜测的标题。创建已知路径的新文件不先递归扫描目录；用户要求“不支持就停”时，不继续切换应用和准备无用文件。
- [x] G7：证据用于判断结果，不要求简单任务的最终回复附工具名、targetRef、原始状态等证据块。

以上三项约束了 agent 的决策入口，不能保证模型从不误用工具。是否消除了真实任务中的额外往返，需要用同一用户目标复测；不把提示词修改当作模型行为已经验收。

## 参考边界

- Electron 的页内导航事件来自任意框架，主身份必须检查 `isMainFrame`：[官方文档](https://www.electronjs.org/docs/latest/api/web-contents#event-did-navigate-in-page)。
- `contenteditable` 可以继承，不能把每个继承节点都当成独立输入框：[MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/contenteditable)。
- `參考/ZCode/packages/desktop/src/main/browserView/browserPlaywrightLocatorExecutor.ts` 使用正确焦点框架的原生输入，不把自己是否接收到 DOM input 监听回调作为写入成功的必要条件。
- `參考/opencode/packages/opencode/src/tool/glob.ts` 用于查找已有文件，不承担创建一个已知路径文件前枚举主目录的工作；本轮没有更改 glob 的正常递归语义。
- `參考/opencode/packages/opencode/src/session/llm.ts` 将流资源清理绑定到作用域，不仅依赖正常返回后的尾部清理。Rust 对应处理队列票和许可的销毁；[Tokio 取消安全说明](https://docs.rs/tokio/latest/tokio/macro.select.html#cancellation-safety)解释了 future 被丢弃时的边界。
