# 非视觉浏览器动作总审计

Audience: Internal
Status: Active
Last verified: 2026-09-27

目标：一次按人的浏览器动作分类检查，避免让用户逐个网站发现基础能力缺口。本轮检查公开工具参数、Rust 分发与结果呈现、桌面控制器、地图发现、真实浏览器执行五层。纯 Canvas/WebGL 画面识别不在本轮范围。

**结论：常用网页操作的基础能力已得到一批通用修复，但当前还不能宣布“除视觉外，人能做的都能做”。** 目录上传、浏览器原生菜单、系统级窗口与权限等缺口确实存在。动作原语完备，也不能证明任意网站、任意脚本和无限状态组合都已覆盖。

状态含义：

- **已验证**：有本地真实 Chromium/Electron 回归支持，验证的是列出的动作，非所有网站。
- **部分**：有实现/入口，但仍有明确边界或未完成真实端到端验证。
- **缺失**：当前公共工具链不具备完整能力，不能靠提示词算成支持。
- **用户参与**：真实授权、硬件或本人验证；需要可恢复的交接，不应伪造完成。

## 本轮修复清单

- [x] ~~`selectText`、`occurrence`、`repeat` 错挂到点击 schema，按键工具拿不到~~：移回 `browser_press`；旧 capability 描述复用同一份 schema，避免两份契约继续漂移。
- [x] ~~原生 select 的底层参数没有公开，原生弹出选项被当成普通 DOM 按钮~~：公开单选/多选；按真实 select 的标准值契约处理。所有选项先验证，再一次修改；歧义和 disabled 选项不部分执行。
- [x] ~~agent 不知道原生 select 有哪些选项~~：点击/检查原生 select 返回有预算的选项列表，支持 `optionQuery`、`optionOffset`，不打开系统弹出框；选择依据精确 label/value。
- [x] ~~修饰键点击、中键、长按、目标内相对位置无法表达~~：贯通 schema、host、真实 Chromium 事件和命中保护。修饰键仅覆盖本次手势。
- [x] ~~没有非视觉拖放入口~~：新增 `browser_drag`，两端绑定地图真实节点；支持指针拖动和 Chromium 原生 HTML 拖放数据，已测试跨 frame。返回输入回执，不冒充排序/移动已经完成。
- [x] ~~原生 draggable、带 drop 处理器的普通 div 不进入地图~~：补原生声明发现、属性处理器发现及地图提示。`addEventListener`/委托监听且无语义的目标仍有发现边界。
- [x] ~~取消或派发失败可能留下按住的键/鼠标~~：异常清理仍释放输入；拖放取消时取消浏览器拖动、撤销监听和拦截。
- [x] ~~原生 alert/confirm 阻塞后只能重试原动作~~：动作前监听，返回实际消息及任务绑定的 dialog ID；显式 accept/dismiss，防跨任务、跨标签、重放和 effect 降级。模型结果保留 ID。当前验证为 Linux/X11，见平台边界。
- [x] ~~待决原生弹窗后连续动作可能继续运行，切页后丢失弹窗所属 tab~~：停止 thenClick/缓存流程，保留 dialog ID 与 tab 绑定；AX 调用同样带任务身份。跨标签拖放在输入前拒绝。
- [x] ~~刷新已有实现却没有公开工具~~：补 `browser_reload`，保留 tab 身份，经过 navigate effect 校验。
- [x] ~~给日期/颜色等赋值还先点开原生选择器~~：明确原生值路径只聚焦和赋值；文本框继续走真实 Chromium 文本输入。

原生 select、日期/颜色值使用浏览器标准控件契约；它们不同于模拟文本键入。没有请求网站业务 API、直接修改应用内部状态或伪造上传/发送完成。

## 验证方法与执行入口

统一命令：

```sh
LYRA_TEST_CHROMIUM=/opt/google/chrome-beta/chrome node --import tsx tools/browser/run-nonvisual.mts
```

顺序执行真实 Electron 输入、真实 Electron 上传、新动作、Chromium 地图与编辑四套。独立临时 profile、只访问本地 fixture、不读取用户账号、不截图、没有模型参与，不请求网站业务 API。每套记录通过案例数、退出码、耗时和日志；通过数量不足时，即便进程返回 0 也报失败。不是用整机高并发压测来掩盖问题。

本轮批量结果：21 + 15 + 18 + 87 = **141 个真实浏览器案例通过**，最终一轮四套执行合计约 133 秒。这个时间是 fixture 批量执行时间，不能换算为“真实 agent 已达到每任务 30 秒”。该轮包含原生选项查询以及日期/颜色赋值不触发 mousedown 的断言。最后补充的待决对话框停止连续提交、跨标签拖放拒绝、dialog ID 路由另有定向单元回归。

其他检查：新手势跨 Rust→host 的路由/effect、原生 dialog ID 的模型结果保留；单元检查任务/标签/重放边界以及失败后输入释放。旧 `view-manager-semantic-tree.test.ts` 的 JSDOM 回归本轮有 12 项失败，涉及缺少真实 input/trusted event、scrollIntoView 等桩，以及既有语义预期；没有删掉或放宽这些断言来制造全绿。真实执行证据由上述 Electron/Chromium 套件提供；全仓验收仍不能称全绿。

## 下一阶段优先级

1. **先补非视觉高频闭环**：目录/取消选择/清空附件、原生菜单、只读正文选区、下载完成与保存交接、离开确认全生命周期。
2. **处理运行时能力缺口**：prompt、Wayland 原生弹窗、依赖 opener 的弹出窗口；明确哪些属于产品本身能力，不把失败归咎给模型。
3. **按需求补低频能力**：媒体原生控件、打印/导出、触摸/设备。权限和硬件操作需要产品层授权与回执设计，不应默认全放行。
4. **保留真实站点验收**：自动基础套件由开发侧维护；用户只需抽验真实任务体验。任意网站完成率、模型判断和 VPN/服务商延迟仍需实际会话证据。

可以并行设计视觉重构，但不能把以上明确的非视觉缺口改名为“视觉兜底”后宣布非视觉完成。

## 参考实现的工作边界

- 本地 `參考/ZCode/packages/desktop/src/main/browserView/browserCommandScripts.ts`：原生 select 读 options 后选择和发标准事件，不靠 OS 弹出项的屏幕坐标。Lyra 增加了全量选项预校验，避免部分成功后才发现后续值无效。
- 本地 `參考/deepseek-harness/docs/subsystems/browser-use.zh.md`：管理所选浏览器后端与会话生命周期，不实现 Lyra 的地图索引和筛选逻辑。
- [Playwright Input](https://playwright.dev/docs/input)：分别处理鼠标修饰键、select、文件、目录和拖放；文件选择不等于操作 OS 文件管理器。这些是浏览器标准交互，不是网站 API 平替。
- [Playwright Dialogs](https://playwright.dev/docs/dialogs)：同步原生对话框需要在触发前处理其生命周期；忽略它会阻塞页面动作。Lyra 返回待决状态供 agent 显式决定。
- [Electron MouseInputEvent](https://www.electronjs.org/docs/latest/api/structures/mouse-input-event) 与 [webContents](https://www.electronjs.org/docs/latest/api/web-contents)：真实输入事件、原生窗口和页面执行具有不同契约，不能统一假设为 DOM 元素。
