# 连续浏览器操作：地图复用与回复完成观察

## 验收动作

在同一网页连续发送三条消息，每条等到回答后再发下一条。只获取一次初始地图；仍存在的输入框和发送按钮继续使用原引用。页面回复结束后，不应再经过 `textStable → map → wait → map` 的模型往返。输入失败不能发送，发送后的读取失败不能重复发送。

真实 DeepSeek 会话的旧基线：第三轮已经读到最后一句回答后，外层任务又过了 45.283 秒才结束。这包含模型处理和最终回复生成，不能把全部时间归因于工具。原始时间线保留在 [测试调查](browser-upload-retest-2026-09-27.md)。本次没有在用户账号发送新的测试消息，真实网页及模型的端到端时间仍待同一动作验收。

## 已处理项

- [x] ~~输入后为反馈重新扫描全部控件。~~ 普通输入只验证对应编辑器的实际文字、输入事件、校验状态、错误说明和格式限制。保留渲染后的再次验证、遮挡检查及原生输入；`verification=full` 仍可显式要求完整观察。
- [x] ~~点击后每隔 80 ms 重建地图。~~ 使用文档变化记录等待短暂稳定，之后采集一次；如果尚未发现变化，继续观察延迟弹窗并最多补采一次。忙碌状态和无效果点击不会被标记为已稳定成功。
- [x] ~~已知目标仍靠遍历查引用。~~ 物理节点注册表增加 `targetRef → WeakRef` 索引。节点断开后清理；只有实际注册的节点才拥有引用，复制 DOM 属性不能冒用。布局与可操作性依然在真正输入时重新检查。
- [x] ~~模型下一次调用前结束的回复丢失完成过程。~~ 在明确的发送前建立操作编号和 UI 观察。记录新出现的关联停止控件，或由 `aria-controls` 关联的忙碌区域及其结束变化；要求同时存在新渲染的输出。后续 `responseComplete` 读取同一操作的记录。
- [x] ~~等待阶段反复读取整页文字、重新发现发送按钮。~~ `responseComplete` 在等待期间只读取操作状态，完成或超时时才读取回答；完成时复用已有目标，不补一张地图。
- [x] ~~输入、发送、取得回复必须拆成多个模型决策。~~ 需要回复时，模型可在 `communicate` 动作设置 `awaitResponse=true`；输入使用 `thenClick`。同一次工具调用完成一次发送并等待回复，最多等待 30 秒。仅发送消息而不需要回复的任务不设置此选项。
- [x] ~~旧操作状态可能被其他任务或后续操作误用。~~ 状态按任务、浏览器模式、标签页隔离；后续编辑/动作失效旧的待等记录，重叠的新观察替代旧观察，已经返回的完成记录被消费。导航、区域消失和两分钟有效期结束都不会误报完成。

## 边界

这是通过减少不需要的采集和模型往返修复已发现的慢路径，并非宣称所有网页都可以永久缓存整张地图。打开新菜单、弹窗、导航、目标失效，或主动要求地图，仍会获取当前控件；大范围页面更新没有被伪装成已实现的完整增量地图引擎。

文字暂停、旧回答的 Copy 按钮、用户消息的回显、同页无关区域的忙碌结束，都不构成回复完成依据。没有明确关联信号、存在多个独立进度区域、页面被替换时，返回 `unknown`。此时可以使用已经读到的内容或明确条件，不能假装证明回答结束，也不能自动重新发送。条件满足不等同于服务器业务成功，回答或错误正文仍需由 agent 理解。

只读取页面公开渲染的 DOM、控件语义和原生输入结果；没有截图、视觉模型或网站私有 API。实现没有 DeepSeek、QQ 空间等站点判断。

## 参考工作边界

本地 `參考/hermes-agent/tools/browser_tool.py` 的输入路径返回输入回执，不在每次输入后强制让模型重新请求快照；导航路径直接附带可操作快照。参考其减少重复发现的边界，而非替换 Lyra 的地图或输入实现。

[Playwright 的操作性检查](https://playwright.dev/docs/actionability) 在执行具体目标时检查可见、稳定、可接收事件和可用状态，不把整页业务完成作为每个输入的前提。[MutationObserver](https://developer.mozilla.org/en-US/docs/Web/API/MutationObserver) 提供页面变更记录；本实现把记录用于调度采集和保存状态转换，未把“没有 mutation”当作回复完成证明。
