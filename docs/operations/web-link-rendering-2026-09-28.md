# 统一聊天链接渲染

复现动作：在输入框粘贴 `https://x.com/b_nnett/status/2091630242792112480`，紧接着输入中文指令并发送；对比拖入同一网页标签后的显示。

## 原因

- 粘贴产生 `link` 编辑器节点，发送时序列化为完整 URL。
- 拖标签产生 `pageCitation`，发送时保留引用标记及元数据。
- 用户气泡只有遇到引用标记才使用资源渲染器，因此普通 URL 直接显示成原文。
- 原来的域名标签、上次改成的完整 URL、Markdown 原始标签又各用一种显示规则。

参考 OpenCode 的 `參考/opencode/packages/app/src/components/prompt-input/attachments.ts` 和 `build-request-parts.ts`：粘贴文本及请求文本保留原文，不把展示用的缩略内容写回原文。Lyra 保留自己的资源样式，共用显示规则和完整 URL 数据。

## 修改

- HTTP(S) 链接统一显示图标及不含协议头的域名、路径；长地址使用现有资源组件的省略样式。
- 输入框、用户消息、拖入的网页引用和 Markdown 使用相同格式化函数。引用选中的正文和链接图片继续保留原来的内容类型。
- 用户气泡识别普通链接，已有历史消息也适用。点击始终使用完整 URL。
- 粘贴链接的 UTF-16 起止位置随 `webLinks` 元数据保存，避免紧邻中文或 Unicode 路径的边界丢失。后台验证范围、协议及原文一致性，不改变发送给模型的文本。
- 没有元数据的旧消息使用保守的正文链接识别；已丢失的 Unicode 路径边界不能凭空恢复。新粘贴链接保存精确边界。
- 缩略标签不能作为剪贴板内容。选中复制、输入框剪切会还原完整 URL；使用标准 [Clipboard copy 事件](https://developer.mozilla.org/en-US/docs/Web/API/Element/copy_event)，不会读取用户已有的剪贴板。
