## 界面中另外复现的问题

固定动作：加载一条正在思考的会话快照，展开思考框，再收到新的思考增量。文字应该在同一个已展开的框内继续增长。

`withStreamingReasoning` 原来只要找到同一响应的已有 thinking block，就直接返回会话快照。切换回正在运行的会话后，快照包含已有思考内容，但后续增量只进入 StreamStore，不再逐字更新快照；结果是新内容已经到达，界面仍显示旧片段。

对照 OpenCode 的 `session/processor.ts`：已有 reasoning part 继续按 part ID 接收 `reasoning-delta`，只有明确结束才封口；ZCode 的 `reasoning-stream.ts` 也复用已有块。它们不把“已有一个思考块”当成“内容已最终完成”。

修复范围：继续更新当前响应的运行中思考块，保留块 ID 和展开状态；避免把完整实时文本与快照前缀重复拼接，已完成的历史思考仍以持久内容为准。

## 模型设置边界

当前全局 `reasoningEffort` 为默认值，没有证据表明 Lyra 把它擅自提高到最高档。MiMo V2.6 Pro 官方默认开启思考，流式响应先输出思考再输出正文；官方提供开启／关闭开关，并说明思考会增加延迟。[MiMo 官方深度思考文档](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/text-generation/deep-thinking)

没有为了显示“更快”而截断思考、改变用户模型设置或伪造逐字动画。界面修复不能承诺消除上面那次 7 分 42 秒的慢请求。
