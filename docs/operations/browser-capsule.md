# 浏览器胶囊与预览卡顿调查

2026-09-26。用户要求停止占用监控，并把 agent 操作时自动出现的浏览器小窗始终改成胶囊。

## 固定验收动作

启动浏览器任务，在输入框上方出现页面提示时继续输入、滚动消息，点击提示打开对应网页；任务结束后悬停并关闭提示。运行中和结束后都显示网站图标与名称，不出现网页截图小窗。

## 定位结果

| 项目 | 状态 | 证据与含义 |
| --- | --- | --- |
| 小窗后台工作 | 已确认有问题 | 显示约 52×34 CSS 像素的小窗，却每 500ms 最多对 4 个页面执行整页 `capturePage()`，在主进程转 PNG/base64，再经 IPC 发送给聊天界面。 |
| 请求堆积 | 已确认有问题 | 原 hook 使用 `setInterval`，不等待上一轮结束；让 IPC 持续未完成的测试在 3 秒内产生 7 个挂起请求。 |
| 聊天重绘范围 | 已确认有问题 | 原 hook 在 `ChatView` 保存截图数组，每轮 IPC 返回的新对象都会更新整个聊天视图的状态。 |
| 用户报告的完全卡死 | 尚未完成真实场景复测 | 用户因 MiMo 连接失败无法继续原任务，未完成“让小窗消失但不停止 agent”的对照。不能将上述缺陷等同于已经证实的唯一卡死原因。 |
| MiMo `provider transport failed (connect)` | 独立连接问题，未修改 | 错误发生在请求连接阶段；本次没有更改 VPN 或模型路由。 |
| 文档站 `/favicon.ico` 500 | 独立错误，未修改 | 文档站没有该文件，请求落入静态导出的语言动态路由。会增加开发服务器工作，但不足以证明它导致浏览器小窗卡死。 |

参考本地 VS Code 的 `參考/vscode/src/vs/platform/browserView/electron-main/browserView.ts`：它按显式截图请求执行捕获，不为输入框上的页面身份提示每半秒生成整页 PNG。[Electron capturePage 文档](https://www.electronjs.org/docs/latest/api/web-contents#contentscapturepagerect-options)说明了截图接口的用途。

## 已完成

- 始终显示当前页面胶囊；点击现有 live 页面仍打开同一标签页，isolated 页面仍按原行为在工作区打开 URL。
- 删除预览专用的截图、PNG 编码、base64 传输与缩略图样式。`readAgentPreviewPage` 只读取现有页面的标题、地址、图标；不为提示创建或恢复已关闭的页面。
- 刷新在上一轮完成后再安排下一轮，结束或卸载后丢弃迟到结果；页面信息未变化时复用状态。
- 将刷新状态放进独立 `AgentBrowserCapsule`，避免页面提示刷新触发聊天列表重绘。
- 保留结束后悬停关闭胶囊的行为；运行中不提供会销毁 agent 页面 watch 的关闭按钮。
- 占用监控 `lyra-cpu` 已暂停。
