## 根因与修复

- [x] ~~最罕见查询词成为全局硬过滤条件~~。原算法选最高 IDF 的词作为 gate；目录中不存在的词具有最高 IDF，所有工具立即被排除。即使忽略陌生词，某个罕见的替代表达仍可错误排除其他相关工具。改为依据所有匹配词的 BM25 得分排序、按数量上限返回候选，保持精确名称优先；完全没有词重合时仍返回空结果。关键词排序、去重避免词序和重复词无意改变权重。
- [x] ~~空结果暗示能力不存在，缺少恢复路径~~。空结果现在说明这是关键词未命中，提供当前目录分组，并指向已提供的工具定义与 `select:<tool_name>` 精确查询。
- [x] ~~上传执行测试遗漏发现链路~~。新增本次两条原始查询回归，从真实工具目录搜索、写入测试会话发现记录、组装下一次工具列表，直到生成 Chat Completions 请求体并检查上传参数定义。
- [x] ~~旧会话升级缺少明确回归~~。保留旧会话只有 type/act/press/wait 的发现记录，验证无需新建会话即可补入完整上传定义，且不会被延迟加载标记隐藏。这条生产逻辑原本已存在，本次增加验证。

本次修改的是所有工具共享的发现层，没有增加上传专用关键词白名单，没有替 agent 自动执行搜索结果，也没有改动文件上传权限和选取行为。部分关键词命中只能表明“有相关候选”，并不保证该工具满足整项任务；工具名称和定义仍由 agent 判断。

## 参考及取舍

本地 `參考/hermes-agent/tools/tool_search_catalog.py` 明确采用最罕见词准入，目的是压制只匹配通用词的结果；其 `tool_search.py` 在空结果时还返回可用来源和恢复提示。**Hermes 不会把一次词面未命中直接当作能力不存在的证据。** Lyra 原先移植了过滤规则，没有移植这段恢复信息。

[Elasticsearch 官方 match 文档](https://www.elastic.co/docs/reference/query-languages/query-dsl/query-dsl-match-query)将词匹配组合与相关度排序分开，默认采用 OR。这里采用有上限的候选排序，不再把自然语言中的单个罕见词升级为必需约束；另加“服务名称应排在通用动作匹配之前”的回归，防止只修召回而放弃排序。
