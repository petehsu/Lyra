## 对分支的判断

调查时 `research/surface-browser-map`、`main` 和 `origin/main` 都指向 `6a861b64`。新浏览器方案主要在未提交的工作区中，不能只比较分支提交数量判断工作量。更早的 `2cf1e7e3` 文档描述通用 DOM/AX、视觉截图和动作管线；当前工作区已经增加真实节点引用、嵌套操作关系、悬停名称、光标提示、控件状态和动作后地图。

值得保留的是：引用绑定真实节点；页面状态作为证据；动作后的变化直接返回模型。页面的坐标、光标形状和相邻文字可以帮助理解，但不能单独证明一个按钮的身份、用途或操作已经完成。

非视觉、元素引用、按需子树本身已有公开实现。[Playwright MCP 的快照文档](https://playwright.dev/mcp/snapshots)提供元素引用、局部快照和匹配节点检索。因此，不能用“没有其他产品做过”作为质量证据。Lyra 需要在真实节点可靠性、发现不规范控件、输入连续性、输出预算和端到端任务耗时上证明优势。

参考实现的工作边界：

- 本地 `參考/deepseek-harness/docs/subsystems/browser-use.zh.md` 把浏览器操作交给所选后端，自己处理运行生命周期、会话与资源归属；它不实现 Lyra 的地图筛选和编辑器语义。
- 本地 `參考/ZCode/apps/zcode-cli/packages/browser-use-plugin/docs/browser-troubleshooting.md` 在定位器失效后重新获取状态，不用 `first/nth` 掩盖歧义，也不把失效当作擅自更换控制通道的理由。
- Playwright MCP 通过局部快照和检索降低上下文量；它不会把“所有网站信息先塞进模型”作为每次找控件的必要步骤。

## 人类能做什么，当前工具差在哪里

人操作网页时形成的是一个持续的状态：当前页面、正在工作的面板、焦点、光标位置、选区、按住的键、拖动对象和操作后的反馈。单次 click/type 的列表不能完整表达这个过程。

| 人类动作 | 当前状态 | 确切边界或缺口 |
| --- | --- | --- |
| 找名称、查看状态、进入弹窗/菜单 | 已有 DOM/AX、标签、受限悬停、光标提示；本轮补区域检索 | 页面没有暴露任何语义时，不能编造名称。光标不是动作证明 |
| 点击、双击、右键、悬停 | 已有真实节点动作与遮挡检查 | CSS/DOM 目标和 AX 目标的覆盖不同；不能保证所有不规范组件都被发现 |
| 输入、替换选中文字、移动光标、快捷键 | 本轮修复连续编辑与组合键 | `clear=true` 才替换整框；输入框和富文本都遵守此契约 |
| 对某段文字加粗、把当前段落变成列表 | 本轮增加精确选文与编辑状态反馈，并验证按钮式列表工具栏 | 不把自定义编辑器内部数据模型当作通用接口；格式读数反映原生编辑状态 |
| 多选、Shift/Ctrl 点击、长按、拖放、拖动滑块/尺寸边缘 | 已补核心手势并做真实 Electron 回归 | 修饰键/中键/长按、DOM 引用拖放、原生 select 已贯通；复杂尺寸调整/远距离自动滚动仍需专项验证 |
| 滚动、翻页、展开后继续查找 | 已有滚动，已补屏幕外普通控件索引 | 虚拟列表尚未挂载的行、尚未展开的菜单不是已知节点；必须真实滚动或展开 |
| 原生选择框、日期控件、文件选择器 | 部分可通过键盘或专用流程操作 | 内部存在 select 路径，但不能据此宣称所有原生弹层都已稳定覆盖；需要独立回归 |
| 切换标签页、继续同一任务 | 会话与模式隔离的页面登记表、元素归属校验；打开辅助网站默认保留原页；真实浏览器历史导航 | 任务选择独立于前台和预览；多个 turn 共用页的释放已回归。应用重启或缓存丢失后仍须重新定位，不承诺恢复未提交网页状态 |
| 原生系统权限窗口、系统剪贴板、上传下载的完整交付 | 有相关基础设施，非本轮完整验证范围 | DOM 地图不能直接覆盖操作系统窗口；文件传输还涉及权限、路径与结果确认 |
| 理解纯位图、画布绘图、没有可访问语义的像素区域 | 非视觉方案的边界 | 留给后续视觉方案，不使用截图掩盖当前非视觉失败 |

通用动作层下一步应优先补“修饰键点击”和“按引用的拖放”，共用节点存活、遮挡、取消后释放按键/鼠标、结果验证；不为各网站分别写脚本。拖放还必须区分指针拖动、HTML 原生 drag/drop、跨滚动容器拖动，不能用一个坐标移动成功假装三者都完成。

标签页身份、导航默认行为、任务使用权及验收边界详见[2026-09-26 会话修复清单](../operations/nonvisual-browser-session-root-fixes-2026-09-26.md)。

## 大页面的地图规则

采集索引和给模型的展示是两个独立层次。

1. 已发现的普通 DOM/ARIA 控件，包括屏幕外控件，保留真实 targetRef。取消“超过 24 个就不收录屏幕外控件”的采集限制。
2. 短地图以完整条目控制在 6,000 字符以内；大变化的动作回执可以再带一行变化计数。不会在传输末尾把半个控件切掉。
3. 默认优先级来自页面证据：当前焦点、焦点所在的具名区域、弹窗/菜单、验证错误、表单字段、是否在当前视口。不是对按钮文案做“重要/无用”的永久分类。
4. 区域由真实 dialog、form/fieldset、landmark、行上下文及 frame 组成。区域文字相同可能代表同名组，最终动作仍必须使用真实 targetRef。
5. `browser_map` 的 `query` 搜索完整已观察索引中的名称、角色、说明、上下文、链接地址和引用；`region` 限定区域。清空过滤即可找回其他区域。
6. 地图显示匹配数、已展示范围、下一页 cursor。cursor 绑定页面、过滤条件和排序后的节点集合；集合改变时拒绝接着翻旧页，要求从当前索引重新开始，避免漏项和错位。
7. 默认地图突出状态；名称/值的较长展示可以缩略。用完整 targetRef 查询可取得该控件的详细条目。更长正文由页面读取工具取得，不靠无限扩张操作地图。
8. Controller 保存完整索引，工具传输只带当前呈现条目和计数；不把完整 DOM/目标数组/语义树反复复制到模型结果中。

**不按用途永久删除协议、隐私、帮助、页脚链接。** 用户的下一项任务可能就是查看或处理它们。同样，不因一个链接“可以直接访问 URL”就排除它；链接可能携带当前页面状态、弹窗行为或有副作用的动作，不能自动改成后台请求。

**完整已观察索引不等于完整网站。** 当前光标候选扫描、影子根发现和框架遍历仍有成本上限；遮挡区域、无法访问的 frame、未挂载内容都可能形成覆盖缺口。短地图保留相关 coverage 提示，不能把“没有匹配”直接推断为网站没有该功能。确定的普通控件先完整保留；不确定的候选不谎称已验证。

在高频动态列表里连续分页可能不断失效。此时应优先用名称/区域缩小集合；本轮没有加入冻结网站或盲目沿旧分页游标继续的行为。

## 连续动作规则

- 声明的 effect 从 Rust 到桌面保持一致；observe 缺省为 hover，矛盾的显式手势被拒绝。页面跟随、聚焦、鼠标移入后重新检查真实节点；DOM／AX 点击共用事件命中保护。inputDelivery 只证明事件接收，不证明任务完成。详见[09-27 修复清单](../operations/nonvisual-browser-session-root-fixes-2026-09-27.md)。
- 聚焦按键目标调用实际节点的 focus，不先点击。按键不应顺带提交按钮；连续方向键不应每次重置光标。
- Electron `sendInputEvent` 使用独立 `keyCode` 和 `modifiers`，不直接传 `Control+b`。DOM 与 AX 两条输入路径共用转换。参见 [KeyboardInputEvent](https://www.electronjs.org/docs/latest/api/structures/keyboard-input-event) 与 [InputEvent](https://www.electronjs.org/docs/latest/api/structures/input-event)。
- `browser_press` 可用 `selectText` 在指定可编辑节点内选中唯一文本，再按快捷键。重复文本必须给更明确的文本或 1-based `occurrence`；不唯一、不存在、节点失效时不发按键。
- `repeat` 仅批量重复导航/选区键，最多 50 次；发送、删除、提交等激活键不允许重复执行。
- 文本和选文参数在 host 边界保留原始空格、换行；显式清空允许空字符串。
- 富文本输入保留现有选区；选区不属于目标时才移到末尾。拒绝输入时不以直接改 `textContent` 的办法破坏编辑器结构和撤销历史。
- 页面上下文返回当前编辑控件、选区起止、选中文字、折叠状态和原生加粗/斜体/下划线/列表状态。偏移量基于 DOM 文本的 UTF-16 长度；跨段落可见换行与 textContent 不完全一致，精确选文遇到不匹配要明确失败。
- 同一模型批次的浏览器调用按发出顺序执行，包括观察；其他工具仍可并行。分类同时覆盖旧命名空间与 provider 实际使用的 `browser_press` 等名字，避免排队和暂停控制只对旧工具名生效。排队也计入统一批次期限。此保证不代表不同会话同时操控同一页面已经没有冲突。
- 本地编辑和导航允许合理的 effect 声明；不能把提交快捷键降成 observe 绕过动作分类。

## 固定复测动作与验收

真实任务维持此前失败的操作：在 Gmail 草稿中填主题和正文；把预算改为 500；整理列表、加粗指定句；追加雨天安排；关闭再打开草稿检查保存。大页面另检查已知页脚链接能否通过地图搜索找回，不能只看地图数量。

自动回归使用真实 Chromium，执行生产采集器、真实节点引用与输入控制器，不加载用户账号，不截图，不用网站业务 API。新增回归检查：大型邮箱旁的写信字段、屏幕外链接的检索与真实点击、分页完整性与失效游标、组合键线路、文字替换、加粗、工具栏列表、追加后保持列表结构、同文多段重写、重复文本歧义、聚焦按钮不误点击、AX 快捷键、跨会话 tab 归属、批次动作顺序。

这些用例验证浏览器基础机制，不包含真实 Gmail 实现、模型决策和网络延迟。性能比较必须分别记录模型等待、工具执行、重复观察和恢复轮数；真实任务还要检查 `browser_see`/`browser_vact` 与图片输入是否为零。不能把本地动作的毫秒结果当作整个 agent 任务已经达成 30 秒。
