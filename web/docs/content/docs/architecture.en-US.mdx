## Layers

1. App Layer: `apps/desktop`
2. Service Layer: control-plane, automation, agent orchestration (phased)
3. System Layer: Rust system capabilities and sandbox
4. Shared Contracts: protocols and plugin SDK

Rule: dependencies can only move downward through explicit contracts.

## Module boundaries

Lyra module shape:

1. `types.*`: contracts
2. `service.*`: core behavior
3. `index.*`: single public entry
4. `tests/*`: module tests

Anti-patterns:

1. Growing god files.
2. Cross-module deep imports (`../../other/internal/*`).
3. Shared mutable global state.

## Rich document rendering

Docs can render markdown through the same Rust `lyra-render-core` pipeline used by the desktop AI panel. The web build loads `lyra-render-wasm` in the browser for RaTeX math and merman diagrams. Tree-sitter highlighting remains native-only until the browser runtime can link the tree-sitter C runtime for `wasm32-unknown-unknown`.

## Engineering guardrails

1. Keep source files under 420 lines.
2. Shared size/color must be token/theme driven.
3. UI copy must go through i18n keys.
4. UI changes must pass style guard scripts to prevent “web-card” regression.

## ADR process

Major architecture decisions are captured as ADRs.

Current key ADRs:

1. `ADR-0003`: Workbench shell composition and tab-evolution readiness.
2. `ADR-0004`: File editor foundation (Rust + Monaco).
