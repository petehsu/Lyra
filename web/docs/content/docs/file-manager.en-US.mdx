## Positioning

File Manager is not a browser-tab special case. It is a first-class workspace app tab.

It validates Lyra's software model:

1. real software can run inside workspace tabs
2. strict separation between UI and native capability layers
3. future plugins/apps can onboard through the same host model

## V1 scope

1. Directory navigation (home, directory, trash).
2. Favorites and recent locations.
3. Create folder and create file.
4. Move to system trash.
5. Browse, restore, and empty trash.
6. List view and large view (with image preview support).

## Native bridge principles

1. Renderer never accesses Node `fs` directly.
2. All operations go through preload + main + Rust NAPI bridge.
3. If native capability is unavailable, degrade locally without breaking workspace.

## Icons and skeletons

1. File-type icons come from a registry, not ad-hoc extension logic in components.
2. Loading states use view-aware and data-aware skeletons.
3. Skeleton display is throttled to avoid flicker on fast responses.
