## Position

Lyra Capability Protocol (LCP) is the public SDK contract for exposing Lyra software capabilities to Agent.

V1 keeps one stable Agent entrypoint: the `software` tool. Agent uses `list`, then `inspect`, then `invoke` for one selected action, so installed software does not expand directly into model tool schemas.

## Manifest

UIUX packs can declare software capabilities in `.lyra-plugin/plugin.json`:

```json
{
  "id": "acme.tools",
  "uiux": {
    "entry": "dist/index.js",
    "workbenchUiApi": "1"
  },
  "contributes": {
    "software": [
      {
        "id": "mail",
        "title": "Mail",
        "description": "Mail workspace actions",
        "actions": [
          {
            "id": "open",
            "title": "Open mailbox",
            "description": "Open the mailbox surface",
            "risk": "navigate",
            "inputSchema": {
              "type": "object"
            }
          }
        ]
      }
    ]
  }
}
```

After installation, Lyra normalizes the external software id to `external:acme.tools:mail` and the action id to `external:acme.tools:mail.open`.

## Runtime

Trusted UIUX packs register action handlers inside `createPack(context)`:

```ts
export const createPack = (context) => {
  const action = context.capabilities.software[0].actions[0];
  context.capabilities.registerActionHandler(action.id, async (input, request) => {
    return { opened: true, actionId: request.actionId };
  });
  return pack;
};
```

The registry only accepts action ids declared by the manifest. Undeclared actions are rejected.

## Risk

Action risk levels:

1. `read`
2. `navigate`
3. `write`
4. `external`
5. `destructive`

Before Agent invokes `write`, `external`, or `destructive`, the `software` tool uses the existing permission request flow. `read` and `navigate` are executable by default.

## Built-ins

Built-in V1 capabilities:

1. `browser-search.openUrl`
2. `browser-search.search`
3. `file-manager.openHome`
4. `file-manager.openPath`
5. `settings.openSection`
6. `software-store.open`
